# 性能记录规则（本仓的"比值纪律"）

这份文件回答一个问题：**什么样的一行 `measured_ratio` 值得被写进 manifest？**
每条规则都来自一次踩过的坑，括注是它能挡住的那个错误。

## 1. 没有比较集就没有比值

- 至少 **4 对同进程交替 A/B**（A,B,B,A...），每对算一次比值，取**配对比值的中位数**。
  （挡：把"今天快、昨天慢"当成算法改进。）
- 比值必须带**它比的是什么**：`measured_ratio` 旁边必然有 `bench` 脚本 + `ratio_note` 说明基线是哪个实现、
  哪个形状、哪天测的。manifest schema 已经把 `bench` 设成必填。
  （挡：一个孤立的 14.15× 在半年后没人知道它是跟谁比的。）

## 2. op 级与端到端口径分开记，不能互相顶替

| 例子 | op 级 | 端到端 | 结论 |
|---|---|---|---|
| `gdn_conv_update` | 14.15× | TileInfer 记 0.995× | 只 opt-in，`note` 里同时写两个数 |
| `gdn_chunk_wu` | 14.55× | 45.6× 孤立 / 1.91× 链 / 1.04× e2e | 三个口径都写，不许只挑最大的那个 |

（挡：源仓 `perf-candidates.md:43` 那类"用 op 级数字说服人开默认、上线后 e2e 没变"的错误。）

## 3. 单窗数字只是 [待复核]，不许晋升

单次运行、单形状、没交替的数字写进 `docs/status.md` 时标 `[待复核]`；只有它变成"有比较集的中位数"才允许
升成 `measured_ratio`。作废的（跑错机器、参数写错、比错基线）标 `[作废]` 并**保留**——删掉等于允许别人
再踩一遍。

## 4. 基线是定义性的 1.0，不是"赢"

唯一实现（或语义就是它本身）的 op，`measured_ratio = 1.0` 且 `ratio_note` 必须写清"definitional / parity"。
它进清单是为了**可见与可回退**，不是为了宣传。（挡：把 5 个 torch 基线读成 5 个优化成果。）

## 5. 比值的方向只写在两处

- manifest：`measured_ratio = 基线耗时 / 本实现耗时`，**越大越好**，门槛 1.0。
- bench 脚本：`time_ratio = 本实现 / 基线`，**越小越好**，因为它是原始测量。

一个脚本同时输出两者并写明 `ratio_convention`。（挡：翻了个倒数还理直气壮。）

## 6. 负结果归档，不删不改

负结果（MoE `grouped_gemm` 0.86×、decode 内核 0.362×、`down_prenz` 算错）留在
`docs/archive-*.md`，写清"为什么负"和"什么条件下可能翻案"。（挡：三个月后有人重新实现一遍同样的负结果。）

## 7. 只有满足条件的实现才能默认开

四道门（见 `docs/status.md`）：总开关 → `enabled_by_default` → `measured_ratio >= 1.0` →
设备/形状/布局/图档**纯数据**接受。缺一条就进不去，且每条拒绝都能在 `describe()` 里读到理由。
（挡：一个只有 950 才有的 vendor 路径被 CPU 机器选中。）

## 8. 一台机器、一个解释器、一套缓存

所有数字出自同一台 `tileinfer-102`、同一个 `.venv_native213`（torch 2.13.0+cpu / torch_npu 2.13.0rc1 /
tilelang 0.1.15 / CANN 9.3）、同一个 `tl_cache_213`。换机器要重新测，不许搬数字。
（挡：把 dev 机器的数字贴到 950 上。）
